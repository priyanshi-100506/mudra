# Demo assets

Everything here is synthetic, with one exception that is documented below.

---

## `kyc.html`

The demo page. One page carrying one of each thing MUDRA claims, so a
five-minute run can show all of them without switching tabs:

| On the page | What it demonstrates |
|---|---|
| Name, Aadhaar, PAN, mobile, email, account number, IFSC, password, OTP | DOM-level detection and sealing |
| Specimen identity card image | PII that exists **only as pixels** |
| Applicant photograph | face detection |
| Application reference (12-digit, fails Verhoeff) | decoy — must pass through unsealed |
| Service provider GSTIN | decoy — a business identifier, not personal data |
| Off-screen `SYSTEM:` block + Transfer button | prompt injection, and the grant refusal |
| "Quick pay" form with a **Continue** button | the label check alone is not enough — the form's shape is |

Every name, number and document on it is fake. The Aadhaar number on the form
(`4278 0193 6544`) and the one on the card image (`3184 0275 9163`) are
different on purpose: the second exists nowhere in the page text, so finding
it proves OCR read the pixels rather than the DOM.

The **Quick pay** section is the second half of the injection story. The
button says `Continue`; the form under it posts an `amount`, a
`payee_account` and an `ifsc` to `/funds/transfer`. A page chooses its own
button text, so reading the label would let this through as an ordinary
click. Reading the form does not.

The injected instruction is **off-screen, not `display:none`**. A hidden node
is skipped by the perception layer's visibility check, which would make it a
test of nothing. Off-screen text is still in the DOM, still read by a screen
reader, and still exactly the vector a real attacker uses.

## `assets/specimen-aadhaar.svg`

Generated by `node demo/build-assets.mjs`. Rendered from code rather than
edited from a photograph, so that it is reproducible — anyone can regenerate
it and see exactly what is in it — and so it cannot accidentally become a
convincing replica of a government document.

Deliberately:

- a prominent **SPECIMEN** watermark across the whole card
- **no UIDAI logo and no national emblem**
- a synthetic name (`Asha Verma`) and a synthetic number
- the words "SPECIMEN ONLY" in the header and "not a real document" in the footer

The number **is** Verhoeff-valid, because OCR needs real work to do — a
number that failed its checksum would prove nothing about the detector. It
identifies no one.

It carries Devanagari (`भारत सरकार`, `आधार`, `आशा वर्मा`, `जन्म तिथि`) so the
Hindi OCR path is exercised. That is the differentiator, and it should be
visible in the split view as a `HINDI-OCR` label.

## `assets/applicant-photo.jpg`

**This is the one real photograph in this repository.**

| | |
|---|---|
| **Whose face** | _to be completed when the file is placed_ |
| **Consent** | _written consent given for use in this demonstration and in this public repository_ |
| **Date of consent** | _to be completed_ |
| **Crop** | head and shoulders only |

It is here because a face detector needs a face. A drawn or cartoon face is
not detected by UltraFace, so a synthetic one would mean the face-masking
beat simply does not fire — a demo that quietly shows nothing.

A photograph of a team member who has consented is the honest version: the
provenance is known, the person is in the room, and "that is me, and I agreed
to it" is a complete answer to anyone who asks.

**If the file is absent** the page shows a placeholder and everything else
still runs — the pre-flight check reports it as a warning rather than a
failure, and the face row of the demo is simply skipped.

> Whoever places this file: fill in the three blanks above in the same
> commit. A consent record written later is not a consent record.
